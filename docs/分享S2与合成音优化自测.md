# 分享 S2 与合成音优化自测

这次修改的是客户端源码。请用 Cocos 重新构建微信小游戏，再用更新后的体验版测试；云函数代码本轮没有修改。好友也要运行同一修复版。没有代为打包或发布。

## 2026-09-14：分享进入时报 gain / 销毁异常

本次已经在现有 `build/wechatgame/assets/main/index.js` 中复现了用户提供的具体错误：仅创建空合成器后调用 `dispose()`，就会抛出 `Cannot read properties of undefined (reading 'gain')`，位置与日志的 97:12601、97:11349、97:11540 一致。

原因：源代码 `[...this.activeVoices]` 被发布编译为 `[].concat(this.activeVoices)`，实际得到的是包含 Set 本身的数组，不是音符数组。清理时把 Set 当成音符读取 `releaseGain.gain`，导致场景销毁中断。与祝福语、录音内容和云函数权限无关。日志里的 5000 是 Cocos 的[重复销毁错误](https://github.com/cocos/cocos-engine/blob/v3.8.6/EngineErrorMap.md#5000)；本次同时去掉了 GameScene 销毁时重新修改按钮和销毁输入拦截组件的动作。

修复：

- Set 转数组改为 `Array.from`，涵盖音符清理、复音统计、分享进入监听、首页 BGM 停止、界面按钮去重和关卡进度合并。Map 的正常遍历不受本次展开问题影响。
- 音频释放可重复调用，已销毁的合成器不能被延迟回调重新打开。
- 等待音频唤醒期间退出场景，回调返回 false，不再访问已置空的合成器；不再停止正在销毁的 Cocos AudioSource。
- 原来的 ES2020 直接执行测试没有覆盖发布编译差异。现在先使用 Cocos 自带 Babel 做相应转换，再运行回归与离线音频测试，并保留能触发旧故障的反向用例。

已通过 `node scripts/verify-release-compat.cjs` 与完整的 `node scripts/verify-share-audio.cjs`。覆盖空合成器、带尾音/提示音的清理、重复释放、分享冷/热启动监听、BGM 停止、界面状态恢复，以及五音色共 25 组离线渲染。没有启动 Cocos 构建，也没有代替微信真机测试。

重新构建后优先测：完全退出小游戏后点卡片；小游戏留在后台时点卡片；从挑战/弹奏中打开另一张卡片。确认直接进入播放、不混入首页 BGM，之后可正常返回和再次进入。

现有 build 仍是修复前版本，必须重新构建。构建后可运行 `node scripts/verify-release-compat.cjs --check-build`，额外直接检查构建产物中的空合成器清理；未重建时该检查应失败。该脚本只读取产物，不修改它。

## 分享

- 云函数兼容回调、Promise 和同时返回两者的环境；读取/写入共用同一入口，保留调用上下文。不自动重试写入，避免重复录音和重复累计成就。
- 增加 20 秒等待超时、完整错误日志和录音结构校验。
- 连续打开不同卡片时，以最新一次请求为准，旧请求不会在之后覆盖新回放。
- 处理挑战中打开好友卡片的状态清理；BGM、节奏、原回放停止，新手引导不弹出。
- 音频唤醒超过 3 秒或失败时允许点击重试；异步音符播放的异常也会被捕获。
- 失败提示保留到关闭，显示阶段与 `分享修复版 S2`，控制台可检索 `[CloudCall:v2]`、`[SharePlayback:v2]`。

现网同名 `then` 异常尚无完整堆栈，本轮完成的是调用兼容、播放保护与可定位错误的修复，不能凭本地测试断言已复现了好友手机上的具体根因。

建议自测：

1. 录制 5～10 秒，停止后分享；另一个微信账号从完全退出状态打开。
2. 好友已在游戏内时再次打开卡片；也测试正在挑战时打开。
3. 连续打开两份不同录音，确认不会混播，曲名/音色对应最新卡片。
4. 暂时断网打开卡片，恢复网络后点击重试；若再报错，截下包含 S2 和阶段的完整提示。

## 琴声

- 默认继续为“流行”，保留已有用户选择的音色。
- 淘汰尾音改为 12ms 平滑淡出，15ms 后停止音源；不立即切断尚有振幅的波形。
- 高通/低通滤波器显式设置 Q，收住默认共振带来的额外频段抬升。
- 限幅器输入先缩为 1/4，再在曲线中恢复小信号增益，增加多音叠加的输入余量，输出峰值目标约 0.95。
- 过滤 NaN/非法琴键、力度与参数，保持包络时间顺序。
- 节奏音纳入停止管理，演奏场景销毁时关闭音频上下文；关闭每次击键的常规日志，保留异常日志。

自测时手机音量保持相同，重点对比“流行 / 深沉 / 空灵”：低音单击、低音快速交替、双音，以及反复进入/退出演奏页。检查清晰度、破音、突然截断、静音和音量是否合适。浏览器离线渲染不能替代微信真机与扬声器测试。

## 自动验证及试听

运行 `node scripts/verify-share-audio.cjs`。工具路径可用 `KALIMBA_TYPESCRIPT`、`KALIMBA_PLAYWRIGHT`、`KALIMBA_BABEL_ROOT` 覆盖。Babel 路径指向包含 `@babel` 的 node_modules 目录。

- 分享保存/读取：返回 undefined、null、Promise、回调与 Promise 同时返回，以及错误、非法音符和异步播放异常。
- 使用 Chrome OfflineAudioContext 直接执行合成器，覆盖五音色、44.1k/48k、无压缩器回退、17 键和低音双击/连弹。
- 输出位于 `output/audio-review-s2/`，不进入游戏 assets，也不增加打包体积。
- `previous-dsp` 是在当前合成器中还原旧限幅曲线、默认滤波 Q 与硬截尾音的受控对比，不是旧发布包完整录音。
- `metrics.json` 含峰值、RMS 和快速连弹区间的最大相邻采样差。相邻采样差是断音风险的辅助指标，不等同于主观音质或失真率。

项目 TypeScript 检查仍有两处既有的 `SheetMusicBackground.ts` 中 `MaskComponent.graphics` 类型错误；本轮修改文件未报告新的类型错误。

API 依据：[腾讯云开发回调与 Promise 示例](https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram)、[Web Audio 规范（WaveShaper 输入映射及 AudioParam 自动化）](https://webaudio.github.io/web-audio-api/)。
