### 行为

- 分享祝福和歌名在生成分享卡前检测；`createPerformanceRecord` 在数据库写入前再检测标题，不能仅依赖客户端。
- 选图后逐张检测原始文件，全部通过且全部加载成功才整组替换；失败保留当前曲谱。
- 老版本本地歌名和图片先显示内置内容，重新检测通过后恢复。不删除旧本地存档。
- 旧分享记录缺少 `contentSecurityVersion: 1` 时，读取接口改用固定标题“《分享演奏》”；录音仍保留。
- 违规：`内容不符合规范，请修改后重试`；额度用尽、待复核、网络/权限错误、超时、未知结果：`暂时不可替换，请稍后重试`。分享入口使用“暂时不可分享”。
- 客户端每次云调用最多等 20 秒，超时不自动重试；旧请求返回不能覆盖已退出/切换的页面状态。
- 选图和分享文案弹窗 120 秒没有回调会结束等待；图片读取 10 秒、卡片导出 10 秒超时即停止本次操作，迟到成功不再生效。正常取消选图不提示错误，权限/接口/超时失败提示暂不可替换。
- 原生键盘在检测期间/页面退出后发来的迟到输入和回车会恢复已通过文字；重复点击分享只保留一次流程，新录音、切模式、离开页面会取消旧流程。
- 新客户端要求创建/读取接口返回 `contentSecurityVersion: 1`。连接旧创建函数时停止分享；连接旧读取函数时只展示固定标题，避免部署遗漏形成审核绕过。
- 演奏和挑战成绩分享均使用生成卡片，生成失败不回退到可能含编辑草稿的游戏截图。分享检查包含最终格式化标题。
- 图片加载部分失败会释放本次新资源，保留原曲谱；重复选择当前图片时不会误销毁仍在使用的旧纹理。

### 接口方案与边界

以用户提供的小游戏官方文档正文为准：
- [文本内容安全识别](https://developers.weixin.qq.com/minigame/dev/api-backend/wxa-sec-check/api_gamemsgseccheck.html)：云调用 `wxa.game.contentSpam.msgSecCheck`。`version: 2`、`scene: 1`（当前用于歌名、分享卡文案等游戏素材）、云端上下文 `OPENID`、`content`；服务端上限 2500 个 UTF-16 单元，客户端产品输入仍限制 200 个以内。审核调用 1 秒超时。
- [图片内容安全识别](https://developers.weixin.qq.com/minigame/dev/api-backend/wxa-sec-check/api_gamesecurity.mediacheck.html)：云调用 **同步** `wxa.game.contentSpam.mediaCheckSync`。传入 `openid`、`version: 2`、`scene: 1`、`media_type: 2`、`media_url`；审核调用 5 秒超时。此接口不需要异步回调或轮询。
- 两种接口都必须返回 `result.suggest === 'pass'`；只返回成功码、缺少结果、未知建议均不放行。兼容 HTTPS 的 `errcode` 和 SDK 的 `errCode`；成功响应省略错误码时仍要求明确 pass，有错误码时必须为数字 0，两个错误码冲突时阻断。明细出现错误、未知结果或风险也不放行。`replaced_content` 不会被当作已批准的新内容。
- `750031`（账号未开通）、`750032/750033`（分钟/每日限额）、身份不匹配、网络异常和超时均返回暂不可替换；云函数日志保留错误码，不记录正文、图片和签名 URL。
- 图片最多 5 张，单张不超过 **10,000,000 字节**，支持接口声明的 jpg/jpeg/png/bmp/tif/tiff/webp/gif，不再施加旧接口的 750×1334 限制；实际展示仍需本机微信解码和 Cocos 加载成功。未用缩略图审核批准未检测原图。
- 流程：读取原图元信息 → 云端 `prepareImage` 返回所属用户临时目录和当前环境 → 客户端 `wx.cloud.uploadFile` 原文件 → 云端校验文件 ID 的环境及用户归属，下载并验证大小/文件头 → 建立服务端随机副本 → `getTempFileURL` 获取可下载 URL → 同步审核 → 清理上传文件与审核副本。这样避免把最多 10 MB 的图片转成 base64 放入云函数请求，也避免审核期间上传文件被替换。
- 客户端不传任意图片 URL、不自报 OpenID；检查失败也进入清理。上传超时后的迟到成功会再次删除临时文件。客户端和服务端清理都是尽力执行，断网/进程终止仍可能留下临时文件，部署时需为两个临时目录配置短期生命周期清理（建议 1 天），不能承诺即时删除。
- 本机核对 `wx-server-sdk@4.0.2` 的接口代理、存储接口和 `getWXContext().ENV`；SDK 的动态 OpenAPI 并不能证明当前 AppID 已开通这两个能力，仍需实际调用验收。
- 不在客户端存放 AppSecret/access_token；云调用由服务端 SDK 处理凭证。

### 官方部署用法核对

腾讯云官方[函数部署说明](https://cloud.tencent.com/document/practice/583/30936)的开发者工具流程是：右键云函数根目录选择“当前环境”，再右键具体函数选择“上传并部署（云端安装依赖）”。新函数也可能显示为“创建并部署：云端安装依赖”。选中的环境必须与客户端调用环境一致。

本机 `cli cloud functions deploy --help` 已核对支持以下参数（先把 `实际环境ID` 换为已经核实的环境，不能直接运行占位命令）：

```sh
/Applications/wechatwebdevtools.app/Contents/MacOS/cli cloud functions deploy \
  --project /Users/haokunhu/Kalinba \
  --env '实际环境ID' \
  --names checkContentSecurity createPerformanceRecord getPerformanceRecord \
  --remote-npm-install
```

`--names` 对应 `cloudfunctionRoot` 下的目录名；`--remote-npm-install` 表示云端安装依赖、不上传本地 `node_modules`。不要用客户端“上传”按钮替代这个云函数部署操作。
